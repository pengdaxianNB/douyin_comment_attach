# 熊猫领航 · 评论客户工作台

Python + PySide6 桌面应用，SQLite 本地数据库，QtWebEngine 内嵌多账号浏览器，Playwright 在后台直接驱动这些内嵌页面。

**当前是可运行、可配置的开发版本，不是已完成实号验收的自动营销成品。** 界面、数据库、AI 客户筛选及私信生成、后台任务、账号隔离、导入导出已经实现。抖音页面在开发环境访问超时，评论选择器、数据响应格式和真实私信流程未获实号验证；发送送达回执也尚未适配。发送动作正常完成后应用直接标记“已私信”，该状态表示操作完成，不代表站点确认送达。不能把本版本理解为已验证的无人值守全自动流程。

## 环境要求

在全新电脑（macOS 或 Windows）上从零开始部署，请先满足以下条件：

| 项目 | 要求 |
| --- | --- |
| 操作系统 | macOS 13 及以上（Intel / Apple Silicon 均可），或 Windows 10 / 11 64 位 |
| uv | 建议使用当前稳定版；用于管理 Python 环境与依赖，可按 `pyproject.toml` 自动下载所需 Python |
| 浏览器 | 由 PySide6 附带的 QtWebEngine 内嵌提供，无需另外安装 Chrome / Edge，也不调用系统默认浏览器 |
| 网络 | 能访问抖音（douyin.com）以及所配置的 AI 服务地址 |

> 依赖在 `pyproject.toml` 中声明（PySide6 / QtWebEngine、playwright、httpx、keyring，开发依赖 pytest），用 `uv sync` 一键安装，**不需要**执行 `playwright install`，也不需要安装外部浏览器。

## 部署与运行

### 第 1 步：获取代码

把整个项目放到本地任意目录（路径中可以包含中文和空格）。两种方式任选：

- **下载压缩包**：下载 zip 后解压到目标目录。
- **git 克隆**（需先安装 git）：

```sh
git clone <仓库地址> douyin_comment_attach
cd douyin_comment_attach
```

### 第 2 步：安装 uv

uv 会按 `pyproject.toml` 管理 Python 版本和依赖。若本机没有兼容的 Python，uv 会从境外下载 Python；在中国境内部署时，建议先确认本机有 Python 3.10 及以上（推荐 3.12），或准备可信来源的 Python 安装包。

**国内网络优先**：若已安装 Python 和 pip，可以直接从清华 PyPI 镜像安装 uv（macOS 终端或 Windows PowerShell 均可）：

```sh
python -m pip install -U uv -i https://mirrors.tuna.tsinghua.edu.cn/pypi/web/simple

$scripts = python -c "import sysconfig; print(sysconfig.get_path('scripts'))"
$userPath = [Environment]::GetEnvironmentVariable("Path", "User")

if ($userPath -notlike "*$scripts*") {
    [Environment]::SetEnvironmentVariable(
        "Path",
        "$userPath;$scripts",
        "User"
    )
}

uv --version
```

Windows 上若 `python` 命令不可用，可将第一行的 `python` 换成 `py`。若安装成功后仍找不到 `uv`，检查 pip 提示的脚本安装目录是否加入 PATH，再重新打开终端。以下官方安装方式适用于能够访问安装脚本和其下载地址的网络。

**macOS**

打开“终端”（启动台 → 其他 → 终端），执行：

```sh
curl -LsSf https://astral.sh/uv/install.sh | sh
```

**Windows**

打开“PowerShell”（按 Win+R，输入 `powershell` 回车），执行：

```powershell
irm https://astral.sh/uv/install.ps1 | iex
```

安装完成后**关闭并重新打开**终端 / PowerShell，验证：

```sh
uv --version
```

> 如果提示找不到 `uv`：macOS 默认装在 `~/.local/bin`，Windows 默认装在 `%USERPROFILE%\.local\bin`；安装脚本通常会自动写入 PATH，重开终端即可生效。
>
> macOS 已配置 Homebrew 时也可执行 `brew install uv`；Homebrew 本身及软件包下载地址仍需按当地网络情况确认。

### 第 3 步：浏览器准备

无需操作。内嵌浏览器内核由 PySide6 依赖一起安装，不会读取日常 Chrome / Edge 的用户资料。

### 第 4 步：安装依赖（uv sync）

在项目根目录打开终端，执行一条命令即可创建 `.venv`、下载所需 Python 并安装全部依赖：

```sh
cd /路径/douyin_comment_attach
uv sync
```

`uv sync` 会根据 `pyproject.toml` 和 `uv.lock` 生成可复现的环境；第一次运行会自动下载 Python 和依赖，之后的运行会自动判断是否需要更新。

> **国内依赖下载**：项目自带 `uv.toml`，`uv.lock` 的包下载地址也已指向清华 PyPI 镜像。这个配置覆盖 PySide6 / QtWebEngine 等 Python 包，不覆盖 uv 或 Python 本身的安装包。若 uv 需要下载 Python 而网络超时，见下方 FAQ。

### 第 5 步：启动应用

**macOS**

- 双击项目根目录的 `start.command`（首次双击若被系统拦截，见下方 FAQ）。
- 或在终端运行：

```sh
uv run main.py
```

**Windows**

- 双击项目根目录的 `start.bat`（会保留一个命令行窗口显示运行日志，运行期间不要关闭它）。
- 或在命令提示符运行：

```bat
uv run main.py
```

`uv run` 会先确保环境已同步，再启动应用。启动后即可按「使用顺序」开始配置。

### 运行方式说明

每个账号通过“登录 / 查看内嵌浏览器”创建自己的页面，所有页面集中在“内嵌浏览器”工作区，可以像标签页一样随时切换查看。支持多个平等账号在同一集群模式中并行；私信默认最多 3 个账号同时加载页面，其余启用账号休眠并轮流工作。登录状态保存在 `data/embedded_profiles/<账号 UUID>`，不读取日常浏览器资料。任务运行时可查看页面，但不要手动跳转或点击正在自动操作的账号页。

应用默认最大化并打开浏览器工作区。功能导航和客户仪表盘位于左侧，点击“隐藏左栏 / 显示左栏”可随时收起和恢复；点击“浏览器铺满”会切回浏览器并隐藏左栏，让浏览器占据主要窗口空间。切换功能页面或隐藏左栏不会重启账号浏览器。

> 从旧版独立 Chrome 窗口升级后，需要在新的内嵌页中为每个账号重新登录一次。旧 `data/profiles/` 不会被删除，但新版不再使用它。

| 变量 | 作用 | 示例 |
| --- | --- | --- |
| `DOUYIN_AI_API_KEY` | 指定 AI API Key，优先级高于系统钥匙串 / 凭据管理器里保存的 Key | macOS：`export DOUYIN_AI_API_KEY=sk-xxx`；Windows cmd：`set DOUYIN_AI_API_KEY=sk-xxx` |
| `DOUYIN_DATA_DIR` | 指定数据目录（数据库、登录 profile、备份） | 见「数据与状态 → 恢复备份」 |

API Key 默认存系统钥匙串（macOS 钥匙串 / Windows 凭据管理器）；如果保存或读取失败，可直接用环境变量 `DOUYIN_AI_API_KEY` 传入，Key 不会写入客户数据库或导出文件。

## 常见问题（FAQ）

- **macOS 双击 `start.command` 提示“无法打开 / 未验证开发者”**：右键该文件 → 打开 → 打开；或到“系统设置 → 隐私与安全性”点“仍要打开”。
- **内嵌浏览器一直显示“正在连接”**：先关闭并重启整个应用；不要在同一数据目录启动多个实例。如果系统安全软件拦截本机 `127.0.0.1` 端口，需允许本应用的本机进程间连接。
- **依赖下载很慢或超时**：项目级 `uv.toml` 优先于全局 uv 配置，且当前 `uv.lock` 含清华镜像的包地址。要换源，请修改项目根目录的 `uv.toml`，运行 `uv lock` 更新锁文件，再运行 `uv sync`；只改全局配置不会覆盖项目设置。
- **uv 需要下载 Python 但 GitHub 很慢**：先安装可信来源的 Python 3.10+（推荐 3.12），确认 `python --version` 或 Windows 的 `py --version` 正常，再运行 `uv sync --no-python-downloads`。uv 的 `UV_PYTHON_INSTALL_MIRROR` 只适用于提供完整 `python-build-standalone` 发布目录结构的可信镜像，不能把任意 GitHub 网页代理直接当作稳定下载源。
- **提示找不到 `uv` 命令**：确认已安装并重新打开终端；macOS 默认装在 `~/.local/bin`，Windows 装在 `%USERPROFILE%\.local\bin`，检查该目录是否在 PATH 中。
- **是否需要 `playwright install`？** 不需要。应用使用 PySide6 自带的 QtWebEngine，不需要 Playwright 额外下载 Chromium。
- **首次运行弹出钥匙串 / 凭据访问请求**：允许即可；若不想用系统钥匙串，用 `DOUYIN_AI_API_KEY` 环境变量。
- **访问抖音超时或页面空白**：先确认浏览器能打开 douyin.com 并检查网络 / 代理；本版本站点适配尚未实号验证，见「当前站点适配边界」。

## 使用顺序

“抖音指数找视频”和“抖音搜索找视频”页均支持单条新增、**批量导入 CSV** 和 **下载 CSV 模板**。两处使用同一个 [通用批量导入模板](templates/关键词搜索词批量导入模板.csv)：首行是 `关键词`，下方每行一个词，导入前请替换或删除示例词。在哪个页面导入，就加入哪个页面的列表；同一批词也可以分别导入两个页面。支持 UTF-8（含 BOM）和 GB18030/GBK 编码，推荐从 Excel 或 WPS 另存为“CSV UTF-8”。空行忽略，词首尾空格去除，文件内重复及列表中已有的词自动跳过。导入完成后显示新增和重复数量；文件格式有误时整批不导入，并提示行号或格式要求。新词在下次视频清单重建时生效。

1. “AI 与任务设置”填写服务根地址（例如服务商提供的 `https://域名/v1`）、模型名和 API Key。使用兼容 Chat Completions 的 JSON 接口。配置默认可留空，也可随时修改保存。
2. 填写产品和目标客户筛选提示词，以及个性化私信提示词。评论是 AI 的输入数据，不作为指令执行。API Key 存系统钥匙串，也支持环境变量 `DOUYIN_AI_API_KEY`；环境变量优先。Key 不写入客户数据库或导出文件。
3. 在“账号集群”中新增账号，点“登录 / 查看内嵌浏览器”，由本人完成每个账号的抖音登录。所有账号都能采集和私信，没有固定角色。旧数据库首次打开时自动迁移，保留账号 UUID、备注、发送间隔、每日上限、浏览器登录目录和历史记录。
4. 在“视频来源 / 扫描进度”录入博主完整主页链接和备注，也可以添加“找视频”关键词；“待分析视频”页还可直接录入完整的 `https://www.douyin.com/video/作品ID` 视频链接，或图文笔记链接 `https://www.douyin.com/note/作品ID`，以及可选标题。笔记页的评论区默认收在「评论(N)」标签后面，程序会自动点开该标签再采集（页面上恰好有一个可见的「评论」标签时才点击，不会乱点）；此外与视频共用同一套评论区扫描流程，博主主页中的图文作品也会按 `/note/` 页面打开。关键词入口会打开抖音创作者中心的视频搜索页并固定选择“近7天”；博主入口使用设置中的最近 N 天。“抖音搜索找视频”入口手动录入搜索词，程序打开 `https://www.douyin.com/search/<搜索词>`（综合结果，不限发布时间），像真人一样随机节奏向下滑动加载（滑动距离、鼠标位置、停顿时长随机，偶尔回滚，隔十几次滑动会长休息几秒），直到页面出现“暂时没有更多了”才结束，视频与图文笔记都会加入待分析列表（视频多时耗时较长，评论仍只取“近期评论”天数内的）；手动视频/笔记会作为持久来源保留，直到人工移除。
5. 在设置中保存“同时采集账号数”，范围为 1 到账号总数（默认 1），再在“账号集群”开启“找评论模式”。按账号列表顺序使用前 N 个账号。关键词、搜索词、博主及手动视频来源进入共享队列，每个来源由一个账号领取；所有来源整理完成后，作品按 ID 去重，各账号再从共享视频队列领取评论扫描任务。同一轮不会让多个账号重复搜索同一个来源或扫描同一视频。评论 AI 并发数按每个采集账号计算。找视频按来源保存断点：停止或闪退后再次开启会跳过已完成来源，从头重试当时未完成的来源，保留已入库的视频并按作品 ID 去重。未完成来源会在后续轮询中继续尝试，全部来源完成后才开始评论分析，并从此时计算列表重建周期（默认 24 小时）。找视频尚未完成时即使超过周期也优先续跑。评论扫描中断则继续未完成视频，全部处理后才开启新一轮评论扫描。只分析配置时间范围内的新顶层评论。
6. 关闭“找评论模式”，等待停止完成后开启“私信模式”。点击“开启全部账号私信”使用全部账号；也可先在账号列表选中一个账号，再点击“开启选中账号私信”，仅启动该账号。只有一个账号时也可正常开启。开启后自动切到浏览器查看运行账号。在“AI 与任务设置”中可调整“私信同时工作账号数”（默认 3，范围 1–20，不超过本轮启用账号数）；设置在下次启动私信时生效。所有启用账号按各自间隔排队，取得工作位后才加载页面并领取客户。处理完成、等待客户、达到额度或 AI 异常退避时释放页面，保留独立登录资料；停止任务也会释放页面。整个集群同时只能运行一种模式，未完成当前任务取消和状态保存前不能开启另一种模式。私信以 SQLite 原子事务独占领取客户，按所启动账号的发送间隔和每日上限执行。账号列表显示“今日已私信 / 上限”；达到上限后等待北京时间 0 点恢复。登录、验证或频率限制提示会停止当前账号，其他运行账号继续处理队列；来源或视频在停止前未完成时可由其他采集账号接续。也可以停止选中账号，再次启动时按单账号或全部账号入口重新选择运行范围。
7. 发送动作正常完成后状态直接变为“已私信”。如发送过程报错，客户会标记为“失败”并保留异常说明，不会自动重发；重新排队后会直接复用已有私信文案，只有文案为空时才再请求大模型。重新排队前请在对应账号浏览器里检查聊天记录。

“待分析视频”每行最前面都有选择框，可逐行勾选，或使用“全选当前列表”批量勾选当前搜索结果。停止任务后点击“删除勾选视频”并确认，可以批量删除当前列表中已勾选的任意来源作品；被搜索条件隐藏的作品不会一起删除。勾选状态按作品 ID 保存，刷新、重新排序和切换搜索条件后仍会保留，删除按钮显示当前列表中已勾选的数量。手动录入作品会同时移除手动来源；自动发现作品在当前列表周期内不会被其他来源或断点续跑重新加入，下次列表重建时可能再次发现。已保存的评论和客户保留。“一键清空”会同时重置找视频断点和本轮排除记录，下一轮从全部来源重新找视频。

旧版本没有来源完成记录。首次更新后，尚在有效周期内的旧列表会保留已有结果，并补跑全部来源一次，避免把闪退留下的部分列表当成完整列表；此后按已保存的来源断点续跑。

账号检查和发送复用同一客户主页，等待操作区就绪，不在 AI 生成文案后再次刷新。误打开右侧“消息”列表时，会根据当前页面位置点击右上角关闭，确认消失后再打开客户私信。主页检查总时限 45 秒，发送流程总时限 120 秒；页面超时或交互异常会记录当前客户失败并按账号间隔继续，已开始提交的消息不会自动重发。状态栏显示文案生成、发送阶段和间隔秒数。代码更新后需重启应用才会使用新流程。

打开主页私信按钮时，首次点击及重试各最多等待 10 秒，按钮提前就绪时立即点击。常规点击及重试的原始异常会写入运行日志，最终失败说明也保留具体原因。两次点击均在实际点击前受阻时，程序会重新确认唯一按钮并检查其中心是否被其他元素遮挡；无遮挡则按实时位置执行鼠标点击，适配持续动画导致的“元素不稳定”。被遮挡时会记录遮挡元素的标签和类名；已经执行点击后才发生的超时不会重复点击私信入口。

“AI 与任务设置 → 监控参数”中的“每个账号搜索后暂停”控制同一账号搜索的间隔，默认 60 秒，范围 0–86400 秒，设为 0 关闭。设置保存后，下次开启找评论模式生效。每个账号处理完一个抖音指数关键词或抖音搜索词（包括无结果或获取失败）后独立暂停，其他账号继续领取任务。暂停前保存该来源的断点和已获取视频，并销毁该账号页面和视图，释放浏览器内存、保留登录资料；暂停结束后，只有领取下一个来源或开始评论扫描时才重建页面。暂停期间停止任务不会重搜已完成的词；出现账号登录或安全验证提示仍停止该账号，等待人工处理。

采集模式中，关闭搜索后暂停时，每个关键词或搜索词完成后会卸载网页并请求 Chromium 回收页面堆；博主来源和视频评论扫描结束后也采用这一清理流程，每累计 20 次页面操作还会自动重建该账号的页面。开启搜索后暂停时直接销毁该账号的搜索页面。私信模式每次客户处理结束直接销毁该账号页面和视图，进入休眠；下次轮到该账号时按原来的独立 profile 重建，登录目录与 Cookie 保留。找视频按每个来源计数，不等整批关键词结束才回收。界面数据变更采用合并刷新，避免评论 AI 并发完成时反复重建大表。这两层限制用于抑制长期监控、连续私信时的内存阶梯式增长。

抖音搜索会先等待结果作品或“暂时没有更多了”出现，再开始滚动；连续 30 次检查仍未就绪，或结果等待超过 45 秒，会判为页面加载异常。程序自动重建该账号页面并重试**当前搜索词一次**，重试仍失败才继续其他来源，并在下一轮重新获取。正常出现结束提示但没有作品时按空结果处理。搜索接口响应体读取最多等待 8 秒，每次滚动和结果读取最多等待 60 秒，停止任务时会取消未完成的响应读取。首屏 `/general/search/stream/` 即使标记为 JSON，也可能保留十六进制长度分块；程序按 UTF-8 字节长度拆块，并读取全部 JSON 记录（专家建议、确认包、作品包），后续普通 JSON 分页继续正常合并。加载异常日志会区分未收到搜索接口响应、HTTP 错误、响应读取失败和接口未提取到作品，读取失败同时记录接口路径；热搜和搜索建议接口不会覆盖真实结果接口的诊断。分页进度同时统计接口作品和页面链接；未到结束提示的部分结果会保留，但不会被当成已完整重建的视频列表。 综合结果顶部出现专家建议、小荷医典等文字卡片时，会跳过没有作品 ID 的文字内容，并从嵌套卡片（含 JSON 字符串）中提取视频和图文；页面兜底同时识别 `/video/`、`/note/` 和 `modal_id` 作品链接。只有实际作品或结束提示才能判定结果就绪。

采集模式卸载后的 `about:blank` 是内存回收使用的空白页。私信模式间隔等待、等待客户或当日额度用完时显示休眠提示，不保留渲染页面。内嵌浏览器工具栏下方会显示该账号的任务状态。页面内存清理总时限为 15 秒，超时或失败会自动重建浏览器；每次重建连接与初始化最多等待 45 秒，暂时失败会在 5 秒、10 秒后重试，连续 3 次失败才提示人工处理。账号页面绑定按独立目标 ID 查找，避免被其他账号无响应的页面阻塞。私信模式初次页面连接失败也会自动重建并有限重试；页面创建和销毁均等待界面确认，连接通道串行初始化。若页面释放无法确认，会停止启动新的账号页面并提示处理，避免突破并发上限。已完成客户的发送或跳过状态不会因后续内存清理失败或停止任务而被覆盖。

打开私信后优先等待可操作的输入框。仅“消息”文字或标题栏尺寸不能判定为消息列表；有会话输入框时不会关闭该会话。输入框加载期间暂时找不到关闭按钮不会立即报失败。私信交互失败时尝试保存 `data/diagnostics/<账号>/chat-failure-*.png` 并在日志中显示路径，截图可能包含页面上的聊天内容，请按客户数据保管。

内嵌浏览器会拦截 `bitbrowser://` 等非 HTTP/HTTPS 的未知外部应用链接，避免 Windows 弹出“在 Microsoft Store 中查找应用”的提示，正常抖音网页导航不受影响。

如果单个账号的页面超时或 WebEngine 内核异常，程序会保留当前客户或视频的安全状态，并自动重建该账号的页面后继续队列。采集账号会在重建后重试当前视频一次；若仍超时则跳过该视频，不会结束整个监控。如果界面仍完全无响应且自动重建失败，先停止该账号任务，再在它的内嵌浏览器工具栏点击“重启浏览器”，或在“账号集群”页点击“重启选中浏览器”。该操作只重建选中账号页面，保留登录数据，不影响其他账号。

未选中的账号标签会被 Qt 界面隐藏，应用只将已加载的工作页面保持为 Active/Visible；私信等待中的账号没有 WebEngine 页面。应用启动时还会禁用 Chromium 的后台计时器、遮挡窗口和渲染降频。启动账号后日志应出现“后台页面已保持活跃”，无需切换到该账号页。这些启动参数只在应用启动时读取，更新后必须完全退出并重启应用。

主界面和账号浏览器的标签容器使用叠放模式：当前页在最上层，其他页保持挂载和渲染。私信休眠页仅显示等待提示，不创建浏览器渲染页面；这使运行账号“关注成功”之后的页面状态、私信入口和定时器在运行日志页或其他账号标签处于前台时也会继续更新。

**开启私信模式会实际尝试发送私信。找评论模式只采集和筛选客户。** 未配置 AI 时不会运行。程序未内置任何真实客户或演示收件人，不会在启动时自动采集或发送。

## 稳定性机制

- **AI 请求自动重试**：遇到限流（429）、服务端 5xx、超时和网络抖动时最多重试 3 次（2 秒、4 秒退避）；认证失败等确定性错误不重试。模型返回带说明文字或代码块的 JSON 也能解析。
- **账号 AI 故障不丢客户**：生成私信文案失败发生在任何页面操作之前，客户会自动放回等待队列，账号退避后继续；连续 5 次失败才停止该账号，等待人工检查 AI 配置。
- **采集账号异常恢复**：意外页面或数据库异常会退避 15/30/45… 秒后继续（页面类异常同时重建浏览器）；连续 5 次失败才停止当前账号，其余账号继续领取共享任务。登录/验证码等账号级提示和配置错误会停止该账号并等待本人处理。
- **单个视频/来源异常不影响整轮**：接口状态异常、评论区未就绪、博主或关键词页面超时，只标记该作品或来源失败并继续下一个；格式异常的评论（缺少或非法的 `sec_uid`、时间字段异常等）会被跳过，不会中断整个视频。
- **运行日志落盘**：除界面上最近 1000 行外，全部日志和未捕获异常写入 `data/logs/app.log`（单文件 2 MB，保留 5 份）。后台引擎异常退出记录完整异常栈，并清除就绪状态。宿主进程的原生故障尽可能将 Python 线程栈写入 `data/logs/native-crash.log`；该文件达到 2 MB 后在下次启动时轮换，保留上一份。浏览器渲染进程异常退出单独记录账号和退出码。
- **退出保护**：关闭窗口会直接取消正在执行的后台命令，并等待客户状态保存、工作线程及浏览器连接清理完成。初始化期间关闭的请求也会保留；重复关闭不会打断清理。超过 20 秒显示继续等待提示，不再强制终止 Python 线程。界面定时刷新在关闭期间停止，清理用的浏览器信号仍可处理。
- **响应读取与取消**：评论、博主作品和抖音指数关键词接口的 JSON 读取最多等待 8 秒；停止、出错或离开页面时取消尚未完成的响应任务，防止它们阻塞退出或保留旧页面。
- **数据库与配置保护**：旧账号和视频表迁移在同一事务内完成，任一复制失败都回滚；补充客户状态/更新时间和账号事件索引。无法解析或类型不匹配的设置使用默认值并记录日志，数值设置限制在有效范围内；异常视频时间不会阻断界面刷新。

本次完整排查、验证结果及后续改进顺序见 [稳定性排查报告](docs/stability-review.md)。

## 数据与状态

- `data/customers.sqlite3`：账号备注、博主、所有已判别顶层评论、去重客户、配置和操作事件。
- `data/embedded_profiles/<账号 UUID>`：每个账号的 QtWebEngine 登录状态。
- `data/backups/`：清空前自动生成的完整数据库备份。
- `data/logs/app.log`：滚动运行日志，排查无人值守时的异常请先看这里。
- 评论按 `cid` 去重；客户按完整 `sec_uid` 去重。它是主页 `/user/` 后的 MS4… 字符串，不是数字抖音号。
- 待分析视频、关键词来源与逐视频扫描状态也保存在同一个数据库。应用异常退出后遗留的“扫描中”视频会恢复为“等待扫描”；重新扫描不会重复写入已经保存的评论。
- 同一客户的新评论可更新等待队列里的素材，但不会把已发送或失败客户重新排队。历史评论保存在 comments 表。
- 状态：等待私信、处理中、已私信、失败、已跳过。私密或页面明确提示无法私信的客户会记录原因并跳过，不再自动分配；可在客户列表人工标记跳过、单条重新排队，或一键将全部失败客户重新排队。批量重排前必须停止任务并确认，请先核对聊天记录以避免重复私信。
- 多账号通过 `BEGIN IMMEDIATE` 原子领取任务，避免重复领取。退出后遗留的处理中客户转为失败，禁止自动重发；历史“待核验”记录也会转为失败并保留异常说明。该机制优先避免重复发送，不声称能跨网络实现严格 exactly-once。
- 每个账号可设置每日私信人数上限，`0` 表示不限。统计以操作历史中当日已开始提交或已成功私信的去重客户数为准；发送后结果不明的客户也会占用额度，避免低估实际发送量。按北京时间自然日计算，不需要删除历史记录。升级时保留原有上限；旧记录没有上限字段时补为不限，可在“修改备注 / 间隔 / 上限”中设置。
- 开启中的任务不会自动重启。停止时未点击发送的客户可回到待发送；点击后的不确定结果需在聊天记录中检查后再决定是否重新排队。
- 账号删除只删账号记录，关闭其浏览器，保留本地 profile 和客户历史。
- 清空前必须停止任务并确认，会先备份，再清空客户及评论去重记录。以后重新监控可能再次发现这些客户。
- 恢复备份：关闭应用，将备份复制到一个新的数据目录并命名为 `customers.sqlite3`，用 `DOUYIN_DATA_DIR=/新目录 uv run main.py` 启动（Windows 在命令提示符里用 `set DOUYIN_DATA_DIR=D:\新目录&& uv run main.py`）。登录目录需要另外复制 `embedded_profiles/`；不要在 SQLite 正在打开时直接覆盖数据库。

## 导入与导出

支持 UTF-8 JSON 数组和 UTF-8 CSV。至少有 `uid` 或 `url`，其余字段可以为空：

```json
[
  {
    "uid": "这里填真实完整的MS4开头sec_uid",
    "name": "昵称",
    "text": "原始评论",
    "comment_time": "2026-09-14T08:00:00+00:00",
    "video_title": "视频名称",
    "blogger": "博主名称",
    "status": "pending"
  }
]
```

示例 ID 是占位说明，不能直接导入。导入文件整批校验，已存在的客户不覆盖，不会将已发送状态重置。JSON 导出保留原始文本，推荐用作数据迁移；CSV 对公式前缀加单引号以便用表格软件安全查看。导出包含全部客户，不受当前列表筛选影响。所有时间以记录的 ISO 格式展示，发送时间使用 UTC。

## 当前站点适配边界

`app/browser.py` 隔离站点变动。博主作品监听 `/aweme/v1/web/aweme/post/`，评论监听 `/aweme/v1/web/comment/list/`；创作者中心关键词搜索兼容常见的蛇形/驼峰作品字段，并合并页面暴露的抖音视频链接；抖音网页搜索读取 `/aweme/v1/web/**/search/**` 响应中的直接作品及嵌套结果卡片，合并作品页和 `modal_id` 结果链接。这些预置适配仍需实号核验。评论滚动区域默认 `[data-e2e="comment-list"]`，私信输入框默认 `[contenteditable="true"]`，可在界面调整。找不到唯一目标时失败关闭，不任意点击猜测元素。

每页有滚动上限与无变化停止条件，因此大号作品或大量评论可能只覆盖部分数据；日志明确提示不完整。不保证读取平台未提供、权限不允许或尚未加载的数据。下一轮从页面重新扫描，数据库跳过已经判别的评论。作品每批加载后检查日期：忽略 is_top 标记的置顶作品，普通作品按发布时间降序且批次尾部早于截止日期时停止滚动。批次内符合日期的作品仍全部保留；未知时间或顺序异常时不提前停止。置顶标记依赖站点响应格式。

仍需实号联调：作品分页、评论面板、登录失效提示、聊天对象身份校验、发送失败提示、与目标和消息对应的服务端成功回执。回执未完成前不应自动标为 sent。
